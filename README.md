**Назначение**: получить практический опыт разработки безопасного backend-приложения с автоматизированной проверкой кода на уязвимости. Освоить принципы защиты от OWASP Top 10 и интеграцию инструментов безопасности в процесс разработки.

## Эндпоинты API

1. **Регистрация пользователя**
- URL:  `POST /auth/register`
  *Создание нового пользователя в системе*.
- Запрос:
```
{
"username": "test",
"password": "test",
"nickname": "testtest",
"email": "test@mail.com"
}
```
- Ответ:
```
"User registered successfully"
```

2. **Логин пользователя**
- URL: `POST /auth/login`
  *Метод аутентификации пользователя с использованием логина и пароля*.
- Запрос:
```
{
"username": "test",
"password": "test"
}
```
- Ответ: JWT-токен
```
{
"token": "eyJhbGciOiJIUzI1NiJ9..."
}
```

3. **Получение данных**
- URL: `GET /api/data?username=test`
  *Метод для запроса различных данных (например, списка пользователей или постов). Доступ разрешен только аутентифицированным пользователям*.
- Ответ:
```
{
"example post"
}
```

4. **Создание комментария**
- URL: `POST /api/comments`
  *Метод для создания нового комментария текущего пользователя. Необходима аутентификация*.
- Заголовки запроса:
```
Authorization: Bearer <токен_здесь>
Content-Type: application/json
```
- Запрос:
```
{
"text": "Текст вашего комментария"
}
```

### Реализованные меры защиты

1. **SQL Инъекция (SQLi):**
   - Используется ORM (Hibernate/JPA) и параметризованные запросы, что предотвращает возможность выполнения SQL-запросов злоумышленниками. Spring Data JPA автоматически создает SQL, что исключает возможность конкатенации строк и инъекций.

2. **XSS:**
   - Сервер возвращает данные исключительно в формате JSON, а не HTML; дополнительно Spring Security обеспечивает защитные HTTP-заголовки. API реализован как JSON-only (@RestController), сервер не формирует HTML-страницы. Все ответы сериализуются с помощью Jackson в JSON.

3. **Аутентификация и авторизация:**
   - Осуществляются с применением JWT-токенов. Каждый запрос проверяется на наличие и корректность токена с помощью фильтра; неавторизованные запросы отвергаются.

4. **Пароли:**
   - Хранятся в базе данных только в зашифрованном виде (с помощью BCrypt). Bean PasswordEncoder создает BCrypt-хешер для безопасного хранения и проверки паролей. Пароли не хранятся в открытом виде и проверяются через метод matches.
